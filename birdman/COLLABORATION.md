# Birdman Claude / Codex 共同作業ガイド

## 共通仕様

物理修正の目的、優先順位、禁止事項、テスト条件は
[`PHYSICS_FIX_INSTRUCTIONS.md`](PHYSICS_FIX_INSTRUCTIONS.md)を唯一の基準とする。

仕様とコードが食い違う場合、実装担当が独断で仕様を変更しない。Issueへ判断事項を記録し、
Claudeによる仕様確認後に実装する。

## 役割

### Claude Fable5

- ゲーム設計と物理仕様の判断
- 距離、故障、6DOF、サーマル、構造モデルの期待挙動を確定
- Pull Requestの挙動・ゲームバランスレビュー
- 実装中に生じた仕様判断をIssueへ回答

### Codex

- コード調査、実装、デバッグ
- 単体テスト・回帰テストの追加
- 描画、当たり判定、UI表示の技術的整合確認
- Pull Requestに変更理由、検証結果、残課題を記録

## ブランチ規則

- 基準ブランチ: `collab/physics-baseline`
- Claudeの仕様作業: `claude/physics-spec-<issue番号>`
- Codexの実装作業: `codex/physics-phase-<番号>`
- 1ブランチでは原則として1つのIssueだけを扱う。
- ClaudeとCodexが同じブランチを同時編集しない。
- 直接基準ブランチへコミットせず、Pull Request経由で統合する。

## 作業順序

1. Claudeが対象Issueと修正指示書をレビューする。
2. 判断が必要な項目をIssueへ明記する。
3. 仕様確定後、Codexが実装ブランチを作成する。
4. Codexがコード、テスト、検証結果をPull Requestへまとめる。
5. Claudeが設計意図とゲームバランスをレビューする。
6. Codexが指摘を修正し、全テスト成功後に統合する。

## Pull Requestの必須記載事項

- 対応Issue
- 修正した不具合
- 変更した物理式または状態遷移
- 追加・変更したテスト
- 3DOFと6DOFへの影響
- セーブデータ互換性への影響
- 未解決事項と意図的に残した近似
- リリースビルドと性能確認結果

## 禁止事項

- 生成物、依存ライブラリ、個人セーブをコミットしない。
- テストを削除または弱体化して変更を通さない。
- 物理修正と無関係なグラフィック変更を同じPull Requestへ混ぜない。
- 既存のユーザー変更をリセット、上書き、破棄しない。
- Issueに記録せず仕様を変更しない。
